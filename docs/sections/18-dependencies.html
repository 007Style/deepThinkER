18 — Dependencies

One of deepThinkER's proudest achievements is how little it depends on. The entire application — with all its features — runs on just six runtime packages. No AI framework. No state management library. No database ORM. No reactive toolkit. Just a handful of small, well-maintained packages for things the Dart standard library genuinely doesn't do.

Deliberately Absent

The following categories of package were considered and explicitly rejected:

  • State management — No Riverpod, BLoC, Provider, GetX, or Redux. Vanilla setState and dart:async streams only.
  • AI/LLM framework — No LangChain, LlamaIndex, or similar. The Ollama API is simple enough that a direct HTTP client is sufficient and far more transparent.
  • Database ORM — No SQLite, Hive, Isar, or similar. All data is plain JSON. It's fast enough, human-readable, and requires no migration system.
  • Dependency injection — No get_it, injectable, or similar. Dependencies are passed explicitly, making the code straightforward to test.
  • Reactive streams — No RxDart. The built-in StreamController is sufficient.
The philosophy: Every dependency added is a dependency that can break, go unmaintained, introduce a security vulnerability, or just make the codebase harder to understand for a new contributor. deepThinkER's complexity lives in its features — not its dependency graph.
