21 — Contributing

Contributions are genuinely welcome. deepThinkER is a project that covers a lot of interesting ground — AI agent design, local inference, macOS development, trust and safety systems, UI/UX for real-time streaming content — and there's good work to be done at every level of the stack.

Quick Start

Contributing Flow
# 1. Fork and clone
$ git clone https://github.com/<you>/deepThinkER.git

# 2. Setup (see Section 14 — Building from Source)
$ git lfs pull && flutter pub get && cd macos && pod install && cd ..

# 3. Run in debug mode
$ flutter run -d macos

# 4. Make your changes and write tests
$ flutter test
00:14 +147: All tests passed!

# 5. Verify zero analyzer issues
$ flutter analyze
No issues found!

# 6. Submit a PR on GitHub

Architecture Rules (Non-Negotiable)

  • 🔒 lib/core/ must be pure Dart. Zero Flutter imports anywhere in core. This is enforced in code review. If you're adding logic to core, your imports must be limited to dart:* and other core/ files.
  • 🧪 New core logic requires tests. The test suite currently covers 147 cases across 14 directories. New features in core/ should come with tests in the corresponding test/core/ directory.
  • 🚫 No new runtime dependencies without discussion. Open an issue first. The minimal dependency philosophy is intentional and maintained carefully.
  • 📋 New tools must implement AgentTool. If you're adding a new tool, implement the interface — don't reach into the interceptor or trust system directly. The framework handles everything else automatically.

Good First Issues

Looking for a place to start? These areas tend to be well-bounded and don't require deep knowledge of the full architecture:

  • Adding a new AgentTool (e.g., a [TIMER: seconds] tool or a [TRANSLATE: text | lang] tool)
  • Improving the RelationshipAnalyser to detect more agreement/contradiction patterns
  • Adding new mood trigger conditions to the MoodEngine
  • UI polish — animations, transitions, accessibility improvements
  • Documentation — the ARCHITECTURE.md is detailed but always benefits from examples and clarifications
Read DEVELOPMENT.md first. The full contribution guide — including branching conventions, PR checklist, debug simulation mode, and how to run individual test suites — lives in DEVELOPMENT.md in the repository root.
Questions welcome. Not sure whether your idea fits the project? Open a Discussion before spending time building it. The best PRs come after a conversation.
