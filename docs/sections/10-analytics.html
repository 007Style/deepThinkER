10 — Session Analytics & Audit

Every session in deepThinkER is fully instrumented. The analytics pipeline captures who said what when, how trust evolved, what tools were used, how moods shifted, and how many tokens each character consumed — all in real time, all saved automatically.

This isn't just for power users. The post-session Analytics screen gives you a visual, human-readable breakdown of what just happened — useful for understanding why a conversation went where it did, or just satisfying the curiosity of watching four AI minds work.

What Gets Tracked

  • 🗓️ Message heatmap — A timeline grid showing who spoke when across the session. Gaps, bursts, and silences are all visible at a glance.
  • 📈 Trust sparklines — Per-character trust score trajectories over the session, plotted as mini line charts on a shared timeline. Watch trust climb, dip on violations, and recover.
  • 🔧 Tool call table — Every SEARCH, FETCH, REMEMBER, RECALL, CALC, FILE_READ, FILE_WRITE, and IMAGE call, with character name, timestamp, input argument, result summary, rate-limit flag, and trust delta.
  • 😤 Mood trajectory — Mood state changes annotated on the session timeline. See exactly when SAGE tipped from Engaged to Agitated, and what triggered it.
  • 🔢 Live token counters — Visible in each quadrant header during the live conversation. Green → amber → red as the context window fills. Resets are shown with a small flash.
  • 🤝 Relationship deltas — Per-pair relationship score changes across the session, showing which pairs moved and by how much.

The Audit Log

Separate from session analytics, the Audit Log is an append-only record of every tool call made across all sessions. It never truncates and is never deleted automatically. Format: NDJSON (newline-delimited JSON) — one record per line, trivially parseable by any tool.

~/Library/Application Support/deepThinkER/audit.ndjson

Each audit entry contains: timestamp, session ID, character name, tool name, input argument, result summary (truncated), success/failure, trust score at time of call, and whether a rate limit was triggered.

The Audit Log screen (accessible from the main menu) renders this as a sortable, filterable table — filter by character, by tool type, by session, by date range, or by rate-limit violations only.

Analytics Export

Analytics for each session are exported as JSON alongside the conversation transcript, and can be zipped into a portable export bundle via the Export button in the Analytics screen.

~/Library/Application Support/deepThinkER/analytics/<session-id>.json
Token counters explained: The counter in each quadrant header shows used / max tokens for that character's current context window. deepThinkER uses a fast token estimator (character-count heuristic, ~4 chars/token) rather than a full tokeniser — fast enough for real-time display, accurate enough to be useful. When a character hits 85% of their context limit, the counter turns amber. At 95%, red. A context reset is triggered automatically at the configurable threshold.
The audit log is immutable by design. It is append-only — there's no delete or edit operation, even from within the app. This is intentional: the audit log is your ground truth for what the characters actually did on the internet. If you need to clear it, you can delete the file manually — but the app will never do it for you.
